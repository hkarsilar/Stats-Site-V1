# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**StatsCapybara** (statscapybara.com) — a free, interactive statistics course: 80+ interactive lessons across 8 courses in two tracks — **The Statistics Core** (Stats 1–4) and **The Research Toolkit** (Methods, Data, Ethics, ML & AI so far; a Writing course is still planned — see ROADMAP.md) — each a written explanation plus a hands-on canvas visualization. It is a **plain static multi-page site**: vanilla HTML/CSS/JS, **no build step, no framework, no npm dependencies, no bundler**. Hosted on GitHub Pages. (One generated asset: `assets/js/search-index.js` — see Full-text search below.)

## Where things live (important)

- **The working directory IS the git repo root** — the folder GitHub Desktop clones as **`Stats-Site-V1`** (remote: `https://github.com/hkarsilar/Stats-Site-V1`). Run `git` commands here directly (just `git <cmd>`, from the repo root). The site's pages, assets, and `CNAME` all sit at this root and are deployed as-is by GitHub Pages from the `main` branch.
- This `CLAUDE.md`, the `.claude/` config, and the two planning docs all live **at the repo root and ARE committed**, so they sync to every machine via GitHub Desktop: **`ROADMAP.md`** (the master development plan — two-track expansion to 9 courses, tools, growth phases, status tracker) and **`PROMPTS.md`** (the numbered, copy-paste session prompts P1–P39 that execute it). If the user pastes a "roadmap prompt PN", read both files first; when a session completes a prompt, tick its box in ROADMAP.md's status tracker.
- Because `.nojekyll` is present, GitHub Pages serves every file verbatim — so these docs are technically reachable at `statscapybara.com/CLAUDE.md` etc. (unlinked and not in `sitemap.xml`, so un-indexed; harmless).
- **History note:** this repo used to be a subfolder named `site` inside a Google-Drive-synced `Websites/` parent, with the planning docs and `.claude/` kept outside the repo. It was flattened so the repo root is now self-contained and Drive-free. If any older note still shows a `site/`-prefixed path, read it as repo-root-relative (drop the leading `site/`).

## Commands

There are no tests, linters, or build tools. The workflow is: edit a file → syntax-check JS → preview in a browser → commit.

All commands run **from the repo root** (the `Stats-Site-V1` folder) and assume only **`node`** on your PATH — Node is the one runtime with the same command name on macOS, Windows and Linux, so preview and the health check need nothing else. **The two content generators are Python 3**; the command name differs by OS, so use whichever your machine has: **`python` on Windows, `python3` on macOS** (this Mac has no bare `python`). Both `tools/*.py` scripts also carry a `python3` shebang and the executable bit, so on macOS/Linux you can run them directly as `./tools/inject-faqs.py` with no interpreter prefix at all.

```bash
# Local preview (zero-dependency Node static server; serve the repo root):
node tools/serve.js 8097
# then open http://localhost:8097/   (Ctrl-C to stop)

# Simulate GitHub-Pages subpath hosting (catches absolute-path regressions):
node tools/serve.js 8088 ..
# then open http://localhost:8088/Stats-Site-V1/   (site behaves as if served from a subpath)

# Site health check — REQUIRED before every commit (exits 1 on any error)
node tools/audit.js

# Syntax-check a shared script
node --check assets/js/site.js

# Regenerate FAQ blocks / search index (Python 3 — use ./tools/… on macOS, python on Windows):
./tools/inject-faqs.py           # or: python3 tools/inject-faqs.py  /  python tools/inject-faqs.py
./tools/build-search-index.py    #     (same three invocations work)

# Syntax-check a lesson's inline interactive (it's the largest <script> block) — pure Node:
node -e 'const fs=require("fs");const h=fs.readFileSync("stats-1/central-limit-theorem/index.html","utf8");const b=[...h.matchAll(/<script>([\s\S]*?)<\/script>/g)].map(m=>m[1]).sort((a,z)=>z.length-a.length)[0];fs.writeFileSync("_c.js",b);'
node --check _c.js && rm _c.js
```

`.claude/launch.json` (committed in the repo, with repo-relative paths) defines the servers above (`site` and `subpath`, plus `site-alt` on 8098 as a fallback when another session holds 8097) via **`node tools/serve.js <port> [root]`**, so the preview tooling spawns identically on any clone — Mac, Windows or Linux — with no Python needed. `tools/serve.js` is a zero-dependency static server (Node built-ins only) that mirrors `python -m http.server`: it serves a directory's `index.html` and 301-redirects a slash-less directory request so lessons' `../../` links resolve exactly as on GitHub Pages.

**`node tools/audit.js` is the permanent health check and a required pre-commit gate** (zero-dependency, Node built-ins only; run from the repo root). It exits non-zero on any **error** and cross-checks the whole site against its single sources of truth: coverage per ready lesson (`CHECKS` 3×4, `faq_data.py` 3 Q&As, `QUIPS`, `SNIPPETS` warn-only, `SOFTWARE` info-only, `sitemap.xml`) with no stale/orphan keys; per-lesson HTML (one GA tag, canonical + `og:url` = true URL, `og:type` article, LearningResource + BreadcrumbList + FAQPage JSON-LD all parse, `data-course`/`data-section`, the `Section N.n` eyebrow vs `curriculum.js`, meta description present + 50–160 chars as a warning); root/tool pages (GA, canonical, description, OG; `404.html` GA only); all internal `href`/`src` links resolve on disk with no leading-slash paths; search-index freshness + slug coverage; and the homepage course/lesson counts vs `curriculum.js`. **Warnings/info never fail the build** — only errors do. Run it (and fix any errors) after every content change and before handing a diff back for review.

Deploy = `git` commit + push (from the repo root) (the user pushes via GitHub Desktop). GitHub Pages serves the `main` branch from `/ (root)`. `CNAME` sets the custom domain `statscapybara.com`.

## Architecture (the parts that span files)

**Single source of truth — `assets/js/curriculum.js`.** Defines all courses and sections (`{ n, slug, title, ready }`, plus `accent` and `track` per course) and a derived flat list. The homepage curriculum grid, every lesson's sidebar, and the prev/next links are all generated from it. To add / rename / reorder a lesson, edit here. A section without `ready: true` renders as a non-clickable "coming soon" item. **Tracks:** `window.TRACKS` is the ordered list of curriculum tracks (`core` → "The Statistics Core", `toolkit` → "The Research Toolkit"); each course carries a `track` (defaulting to `"core"`). `site.js`'s `renderCurriculum` groups the homepage cards by track and draws a track heading (`.track-head`, spanning the grid row) above each group **only when more than one track is populated** — both tracks are populated today, so the homepage shows the two track headings (with a single track it would render one flat grid, as it did pre-Methods). The `.courses` grid is `auto-fit`/`minmax`, so it wraps gracefully as courses grow. Visible homepage totals are computed at runtime from the curriculum: any element with `data-count="courses" | "lessons" | "courses-word"` is filled by `site.js` (`renderCounts`), so they can't drift; the static counts baked into `<meta>`/OG/JSON-LD stay hardcoded and are guarded by `audit.js` check #6 instead.

**Shared chrome — `assets/js/site.js`** runs on every page and builds: the nav (capybara SVG logo + "StatsCapybara" brand; **Curriculum / Statistics Toolbox ▾ / About** — the current page's link gets `.nav-link.active` (lesson pages and the homepage count as Curriculum; on any tool page the Statistics Toolbox item lights up). **Statistics Toolbox is both a link and a menu**: hover/focus drops the full tool menu (CSS-driven, with an invisible hover bridge), while clicking navigates to the `toolbox.html` hub page; on mobile it's a single link to the hub (the dropdown is suppressed). Quiz and Glossary live **only inside the toolbox** — no separate top-level links. There is deliberately **no Ko-fi pill in the nav** (Hakan found it "too desperate"); support links live only in the footer (Ko-fi image button). Also in the nav: a **search pill** (`.nav-search-btn`, icon + "Search" + `/` kbd hint, collapses to an icon under 1200px) + mobile hamburger, theme toggle. site.js further builds the homepage curriculum grid **and toolbox grid**, the lesson sidebar (highlighting the current `data-section`), prev/next, and the Ko-fi image button injected into every footer. The **`TOOLBOX` array in `site.js` is the single source of truth for tool pages** (each entry has a `group`: guide/calc/practice) — it renders the nav dropdown, the homepage `#toolbox-grid`, and (exposed as `window.TOOLBOX`) the grouped grid on `toolbox.html`; add any new tool page there. `site.js` also holds **`QUIPS`**: one capybara one-liner per page (keyed by lesson slug or root file name, with a hash-picked fallback pool), shown in a `.sb-capy` box injected **directly below the highlighted lesson in the sidebar** (always in view). The footer keeps its static "Made for visual learners." tagline — an earlier footer-quip render was deliberately reverted, so tool pages (which have no sidebar) don't surface their quip anywhere visible yet — but **every new lesson/tool page still needs a QUIPS entry** (the audit enforces it). It computes `BASE` (`"../../"` on lesson pages — detected by the presence of `body[data-section]` — else `""`) and prefixes every generated link with it, so all links stay relative; homepage anchors are built as `(BASE || "./") + "#about"` so they also work from root-level tool pages. It also injects site-wide extras once (so no per-page edits): a **skip-link** + `main#main-content`, `role="img"`+`aria-label` on every `.viz canvas`, and the `<link>`s for the SVG favicon / `apple-touch-icon` / `site.webmanifest` / `theme-color`.

**Progress + search live in `site.js` too.** Lesson visits are auto-recorded to `localStorage` (`sc-progress` = `{ slug: {v, d} }`, `sc-last` = the resume anchor). This drives per-course **progress rings** and done/visited dots on the homepage cards, ✓ ticks in the sidebar, a **Resume** banner injected above the homepage grid, and a **"Mark as complete"** toggle injected above each lesson's prev/next. A **search overlay** (magnifier button, or `/` / ⌘K, or a `?q=<term>` URL — that's the target of the homepage `WebSite` SearchAction schema) matches lesson/page titles first, then **full text**: opening the overlay lazy-loads the generated `assets/js/search-index.js`, and body-text matches render below title matches with a `<mark>`ed snippet. **Regenerate the index with `python tools/build-search-index.py` (run from the repo root) whenever lesson prose or tool pages change.** All progress is client-side only — clearing `localStorage` resets it.

**Shared math/canvas helpers — `assets/js/viz.js`** (`window.VIZ`): `fit` (hi-DPI canvas), `css` (read CSS var), `randn`/`gauss`, `erf`/`normCdf`/`normInv`/`normPdf`, `mean`/`sd`, `onTheme`, and exact special functions `gammaln`/`gammp`/`betai` with derived upper-tail p-values `fUpper`/`chiSqUpper`/`tUpper`, densities `tPdf`/`chiSqPdf`/`fPdf`, bisection-based quantiles `tInv`/`chiSqInv`/`fInv`, and exact **noncentral CDFs** `nctCdf`/`ncx2Cdf`/`ncfCdf` (added for `power.html`; reusable by lessons). Lessons and the tool pages rely on these so the statistics are exact, not approximate.

**Tool pages (root level).** `tables.html` = interactive z/t/χ²/F calculator (statistic→p and α→critical value, canvas with shaded tails; all math from `VIZ`). `which-test.html` = "Which test should I use?" decision tree (`NODES`/`LEAVES` in its inline script; step counter + Back button + start-over) plus a cheat-sheet table whose test names link to lessons. `formulas.html` = printable formula sheet (four `.ref-table`s, plain-text/Unicode math — **no KaTeX/MathJax; keep it dependency-free**). `distributions.html` = distribution playground (9 distributions in a config-driven `DISTS` object; binomial/Poisson/Beta pmf/pdf built from `VIZ.gammaln`, normal-approximation overlays for t/binomial/Poisson). `effect-sizes.html` = effect-size converter (d ↔ r ↔ η² ↔ f ↔ OR with overlap/U₃/CLES readouts and an overlapping-normals canvas; verified d=0.5 → r=.2425, OVL=80.26%, U₃=69.15%). `power.html` = power & sample-size calculator (solve any of {power, n, effect size} for one-sample/paired t, two-sample t, correlation, one-way ANOVA, χ², and two proportions; exact noncentral math via `VIZ.nctCdf`/`ncx2Cdf`/`ncfCdf`, verified against G*Power — e.g. d=0.5, α=.05, power=.80 → n=64/group). `descriptives.html` = paste-your-data descriptives calculator (type-7 quantiles, sample SD, t-based 95% CI, adjusted Fisher–Pearson skewness, 1.5×IQR outlier flags, histogram+boxplot canvas, copyable APA sentence). `toolbox.html` = the **Statistics Toolbox hub** (nav's Statistics Toolbox item links here): renders the grouped tool grid from `window.TOOLBOX`, plus pro-tips and a suggested assignment workflow. New tool pages must be added in **four places**: the `TOOLBOX` array (with a `group`) + `SEARCH_PAGES` in `site.js`, the page list in `tools/build-search-index.py` (then rerun it), and `sitemap.xml` — plus a `QUIPS` entry. Canvas tool pages attach both a window `resize` listener and a `ResizeObserver` on the canvas (panel-driven layout changes don't fire window resize).

**Each lesson is a standalone page** at `<course>/<slug>/index.html` (folder + `index.html` → clean URL and refresh-proof on GitHub Pages). Pattern: `<body data-course="stats-N" data-section="<slug>">`, a `.lesson` article with prose + a `.viz` interactive block, then shared scripts (`curriculum.js`, `site.js`, `viz.js`) and the lesson's **own inline `<script>`** holding its unique visualization. Copy an existing lesson when adding one.

**Per-lesson practice — `assets/js/checks.js`** (`window.CHECKS`): 3 "Check your understanding" multiple-choice questions per lesson, keyed by slug (`{ q, o: [4 options], a: answerIndex, why }`). `site.js` lazy-loads it on lesson pages and injects the block as a **closed `<details class="checks">`** ("🧠 Do you want to check your understanding?" — answering is opt-in, not imposed) above the software/APA/snippet boxes (insertion order is safe whichever async script lands first). Every lesson slug must have an entry — verify with a node script comparing `CURRICULUM_FLAT` slugs to `CHECKS` keys. Best scores persist to `localStorage` (`sc-checks` = `{ slug: { c, t } }`), shown as "best so far" on return visits; a perfect run offers a one-click "mark lesson complete" that programmatically clicks the existing `.lesson-done` toggle.

**Per-lesson software + reporting — `assets/js/software.js`** (`window.SOFTWARE`): for every lesson that covers a runnable analysis (~30 slugs), a `{ spss: [steps], jasp: [steps], apa: '<p>…</p>', tips: […] }` entry. `site.js` lazy-loads it and injects two blocks: **"🖱️ Run it in SPSS / JASP"** (tabbed, SPSS is the default tab — steps are HTML `<li>`s) and **"📝 Write it up (APA 7)"** (an example results paragraph in `.apa-quote` with correct `<em>` italics — Latin statistics symbols italicized, Greek not — plus `tips` bullets). Injection anchors keep a deterministic on-page order however the async scripts land: **checks → SPSS/JASP → APA → R/Python → progress head** (APA deliberately sits above "Try it yourself"). Conceptual lessons (no runnable test) simply have no entry.

**Per-lesson FAQ — `tools/faq_data.py` + `tools/inject-faqs.py`.** Every lesson carries a static **"Common questions"** section (3 exam/Google-style Q&As as `<details class="faq-item">`, sky-blue accent) between the prose and the injected blocks, mirrored as a **`FAQPage` JSON-LD** block (`<script type="application/ld+json" data-faq>`) in the `<head>`. Unlike checks/software/snippets these are **baked into the HTML** (not JS-injected) so search engines index them — they're the site's long-tail SEO surface. Single source of truth is the `FAQS` dict in `tools/faq_data.py` (keyed by slug, 3 `(question, answer-HTML)` pairs each; links relative to lesson depth, i.e. `../../`). **Never hand-edit the FAQ blocks in lesson HTML** — edit `faq_data.py`, run `python tools/inject-faqs.py` (from the repo root, idempotent, fails loudly if a curriculum slug lacks an entry), then rerun `tools/build-search-index.py`. Answers deliberately complement (not repeat) the lesson prose and were fact-checked; keep new ones equally rigorous.

**Styling — `assets/css/styles.css`**: a CSS-variable design system. Dark mode is `<html data-theme="dark">`, set pre-paint by a tiny inline script in each page's `<head>` and toggled by site.js. Inter is **self-hosted** (`@font-face` → `assets/fonts/Inter.woff2`); there are no external CSS/JS/font dependencies (except the lazy-loaded Ko-fi button image).

**Per-page SEO & analytics — hardcoded in each `<head>` (no build step, so *not* generated by `site.js`).** Every page carries the Google Analytics 4 tag (`gtag.js`, measurement ID `G-80HCM6EZVN`) immediately after the opening `<head>` — exactly **one per page**, including `404.html`; never add a second. Every indexable page also has a `<link rel="canonical">`; lessons, `quiz.html`, and the tool pages carry Open Graph / Twitter cards built from that page's own `<title>` + meta description plus the shared `assets/og.png` (`og:type` = `article` for lessons, `website` for homepage/quiz/tools); the homepage additionally has a JSON-LD `Course` block, and **every lesson has a JSON-LD `[LearningResource, BreadcrumbList]` block** just before `</head>` (built from that page's own title/description/canonical — retarget it when copying a lesson). `robots.txt` and `sitemap.xml` (home + quiz + every `ready` lesson, as absolute `statscapybara.com` URLs) sit at the site root — **regenerate the sitemap whenever lessons are added, renamed, or reordered.**

## Conventions / gotchas

- **Paths must be relative.** Never use leading-slash `/assets/...` or `/stats-.../`. Lesson pages (depth 2) reference `../../assets/...` and link to `../../<course>/<slug>/`; root pages (`index.html`, `quiz.html`) use `assets/...`. This keeps the site working under any hosting base path. Verify with the `subpath` server above.
- **`404.html` is intentionally self-contained** (inline CSS, no external refs, JS-computed "home" link) because GitHub serves it at arbitrary URL depths.
- **Statistics must be correct.** Interactives are verified against known values (t/F/χ² critical values, G*Power, Beta quantiles). Use the `VIZ` special functions rather than rough approximations, and sanity-check new math (e.g. via `node -e` against a known case).
- **Frozen-noise interactives.** Sliders must transform the *same* data points, never redraw a fresh random sample — students lose the intuition if dots reshuffle on every tick. Pattern used across all lessons: a `seed()` fills pools of fixed `VIZ.randn()` / `Math.random()` draws (sized to the slider maximum); a deterministic `gen()`/`rebuild()` maps `(pool, slider values) → data`; slider `input` handlers call only the deterministic step; the explicit "New sample/samples/people/studies" button calls `seed()` first. Verify with a round-trip: move a slider away and back — every readout must return to the exact same value.
- **Capybara branding is hand-drawn SVG/canvas** — there is no capybara Unicode emoji. Do **not** substitute 🦫 (beaver) or 🐹 (hamster). The mascot lives in `site.js` (`capy()`), inline in the homepage hero, in the OG image, and in `assets/favicon.svg` / `favicon.ico` / `icon-*.png` (the raster icons are regenerated from the same geometry with a Pillow one-liner — keep them in sync with the SVG). Course accents: Stats 1 indigo `var(--primary)`, Stats 2 teal, Stats 3 green, **Stats 4 steel blue `#3b82f6`** (a cool blue that fits the indigo→teal→green family — bluer than Stats 1's indigo so the two don't read the same; the violet `#8b5cf6` only marks the checks block). `#f97316` (orange) is the shared "highlight/marker" accent. **Course accents are chrome-only** (title, eyebrow, sidebar, homepage card): interactive canvas visuals use a course-independent semantic palette — indigo `--primary` = primary series / fitted line, orange `#f97316` = second series / emphasis / residuals, teal `--secondary` = data points / reference, green `#22c55e` / red `#ef4444` = good vs bad status — so a concept keeps the same colour across every course. Never colour a lesson's viz by its course accent. Completed lessons render **fainter** (`--text-faint`) in the sidebar/homepage lists, not darker — the un-finished lessons are the prominent ones.
- **OG image** (`assets/og.png`) is generated by an ad-hoc Pillow script (run inline via `python - <<'PY'`, not stored in the repo). Regenerate it if branding/copy changes; keep its subtitle evergreen so lesson-count changes don't stale it. Absolute `https://statscapybara.com/` URLs now appear on *every* page (`<link rel="canonical">`, `og:url`, the homepage JSON-LD) plus `robots.txt`/`sitemap.xml` — so a domain change is a site-wide find-replace, not just `index.html`.
- **Adding a lesson:** create `<course>/<slug>/index.html` from an existing lesson, set `data-course`/`data-section`, write the inline viz, then flip `ready: true` in `curriculum.js`. The nav, sidebar, homepage, and prev/next update automatically — **but the `Section N.n` eyebrow in each lesson's HTML is hardcoded, so inserting (rather than appending) a lesson means renumbering the eyebrows of every later lesson in that course, plus any lesson-number references in `which-test.html`'s cheat table.** **Because you copied another lesson, retarget its per-page SEO to the new one — the `<link rel="canonical">`, `og:url`, `og:title`/`og:description`, and `twitter:*` title/description all still point at the *source* lesson — leave the single GA snippet untouched, and add the new URL to `sitemap.xml` (which also lists `glossary.html`).** The **visible** homepage counts (hero line + the "N courses" curriculum subtitle) are now computed at runtime from the curriculum (`data-count` spans, see the curriculum.js note above) — they self-update. Only the **static** lesson count baked into `og:description`, `twitter:description`, and the JSON-LD `Course` description (currently `84 hands-on lessons`) still needs manual updating, plus the OG image — and `audit.js` check #6 fails the build if they drift out of sync with the curriculum. Also add a matching **glossary term** in `glossary.html` (each term optionally links back via `{ s: "<course>/<slug>", l: "<label>" }`), a course-tagged **quiz question** in `quiz.html` (`BANK` entries carry `c: "<course-slug>"`, e.g. `c: "stats-1"` — legacy `s1..s4` tags still resolve via a back-compat map; the start-screen picker is generated from the curriculum, so a course appears there automatically once it has questions), an **R/Python snippet** keyed by slug in `assets/js/snippets.js` (site.js injects the "Try it yourself" block on every lesson that has one), **3 check questions** keyed by slug in `assets/js/checks.js`, **3 FAQ entries** keyed by slug in `tools/faq_data.py` (then run `python tools/inject-faqs.py` — it errors on any curriculum slug without FAQs), a **capybara quip** keyed by slug in `site.js`'s `QUIPS`, and — if the lesson covers a runnable analysis — a **SPSS/JASP + APA entry** keyed by slug in `assets/js/software.js`. Then **rerun `python tools/build-search-index.py`** so full-text search knows the new page. If the new lesson introduces a test, consider a leaf in `which-test.html`'s decision tree / cheat table.
- **Adding a COURSE:** append a course object to `window.CURRICULUM` in `curriculum.js` — `{ slug, title, subtitle, accent, track, sections: [...] }`. Give it a `track` (`"core"` or `"toolkit"`; to introduce a new track, add it to `window.TRACKS` in the order it should appear). The homepage grid grows a track heading automatically once a second track is populated; the nav/sidebar/prev-next/quiz-picker/glossary link-builder all read course slugs generically, so nothing else needs per-course wiring. **Accent choice (verify the pick in light AND dark mode, distinct from every existing course accent):** `#8b5cf6` (violet) is reserved for the checks block and `#f97316` (orange) for highlights — never reuse them as a course accent. In use: Stats 1 indigo `var(--primary)` (#6366f1), Stats 2 teal `var(--secondary)`, Stats 3 green `var(--success)` (#22c55e), Stats 4 steel blue `#3b82f6`, **Methods (toolkit) amber `#f59e0b`**, **Data (toolkit) cyan `#06b6d4`**, **Ethics (toolkit) slate `#64748b`**, **ML & AI (toolkit) purple `#a855f7`** (verified distinct from Stats-1 indigo `#6366f1` in both themes — the fuchsia `#d946ef` fallback wasn't needed). Planned toolkit accents (ROADMAP): Writing lime `#84cc16` — and add the new course to this accent list. Then do the **standard lesson integration** for each lesson (see "Adding a lesson"). Course-wide follow-ups: add every ready lesson to `sitemap.xml`; bump the static `84 hands-on lessons` count in `index.html`'s `og:/twitter:/JSON-LD` (the visible hero/subtitle counts self-update; `audit.js` check #6 enforces the static ones); rerun `python tools/inject-faqs.py` and `python tools/build-search-index.py` (both now read course slugs generically from the curriculum, not a hardcoded `stats-*` pattern); and add a quiz question per lesson (tagged `c: "<course-slug>"`).
- **Verifying in-browser:** the preview screenshot tool can hang on external images (Ko-fi, and previously Google Fonts) in restricted-network sandboxes — that's a tooling artifact, not a page bug. Prefer `node --check` + driving the page via eval to confirm behavior; keep external resources lazy/non-blocking.
