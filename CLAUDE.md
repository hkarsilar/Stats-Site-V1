# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**StatsCapybara** (statscapybara.com) — a free, interactive statistics course: 96 interactive lessons across 9 courses in two tracks — **The Statistics Core** (Stats 1–4) and **The Research Toolkit** (Methods, Data, Ethics, ML & AI, Writing — all complete; see ROADMAP.md) — each a written explanation plus a hands-on canvas visualization, plus 19 tool pages (including 3 printable cheat-sheet posters) and 4 long-form guides (see **Long-form guides** and **Cheat-sheet posters** below). It is a **plain static multi-page site**: vanilla HTML/CSS/JS, **no build step, no framework, no npm dependencies, no bundler**. Hosted on GitHub Pages. (One generated asset: `assets/js/search-index.js` — see Full-text search below.)

## Where things live (important)

- **The working directory IS the git repo root** — the folder GitHub Desktop clones as **`Stats-Site-V1`** (remote: `https://github.com/hkarsilar/Stats-Site-V1`). Run `git` commands here directly (just `git <cmd>`, from the repo root). The site's pages, assets, and `CNAME` all sit at this root and are deployed as-is by GitHub Pages from the `main` branch.

If the user pastes a "roadmap prompt PN", read both files first; when a session completes a prompt, tick its box in ROADMAP.md's status tracker.

It was flattened so the repo root is now self-contained and Drive-free. If any older note still shows a `site/`-prefixed path, read it as repo-root-relative (drop the leading `site/`).

## Commands

There are no tests, linters, or build tools. The workflow is: edit a file → syntax-check JS → preview in a browser → commit.

All commands run **from the repo root** (the `Stats-Site-V1` folder) and assume only **`node`** on your PATH — Node is the one runtime with the same command name on macOS, Windows and Linux, so preview and the health check need nothing else. **The two content generators are Python 3**; the command name differs by OS, so use whichever your machine has: **`python` on Windows, `python3` on macOS** (this Mac has no bare `python`). Both `tools/*.py` scripts also carry a `python3` shebang and the executable bit, so on macOS/Linux you can run them directly as `./tools/inject-faqs.py` with no interpreter prefix at all.

```bash
# Local preview (zero-dependency Node static server; serve the repo root):
node tools/serve.js 8097
# then open http://localhost:8097/   (Ctrl-C to stop)

# Simulate GitHub-Pages subpath hosting (catches absolute-path regressions):
node tools/serve.js 8088 ..
# then open http://localhost:8088/Stats-Site-V1/   (site behaves as if served from a subpath)

# Site health check — REQUIRED before every commit (exits 1 on any error)
node tools/audit.js

# Statistical regression gate — REQUIRED whenever viz.js or any tool-page math changes
node tools/math-check.js

# External-link check — quarterly P38 helper, needs the network, NEVER a commit gate
node tools/extlinks.js                                # grouped report: ok / bot-blocked / broken
node tools/extlinks.js --verbose                      # also show which files each link appears in
node tools/extlinks.js --strict                       # exit 1 if anything is genuinely broken

# Voice / prose lint — measures VOICE.md's hard budgets (editorial tool, NOT a commit gate)
node tools/prose-lint.js                              # full report, worst pages first
node tools/prose-lint.js --page stats-1/z-scores-and-the-normal-distribution   # one page, every hit with a snippet
node tools/prose-lint.js --strict                     # exit 1 if any hard budget is exceeded

# Syntax-check a shared script
node --check assets/js/site.js

# Regenerate FAQ blocks / search index (Python 3 — use ./tools/… on macOS, python on Windows):
./tools/inject-faqs.py           # or: python3 tools/inject-faqs.py  /  python tools/inject-faqs.py
./tools/build-search-index.py    #     (same three invocations work)

# Regenerate the per-course + main Open Graph images AND retag lesson heads (needs Pillow):
./tools/make-og-images.py                 # writes assets/og.png + assets/og-<course>.png, then
                                          # points every lesson's og:image/twitter:image at its course image
./tools/make-og-images.py --retag-only    # just retag lesson heads (no Pillow needed)
# (retagging touches every lesson's HTML, so rerun ./tools/build-search-index.py afterwards to refresh its mtime)

# Syntax-check a lesson's inline interactive (it's the largest <script> block) — pure Node:
node -e 'const fs=require("fs");const h=fs.readFileSync("stats-1/central-limit-theorem/index.html","utf8");const b=[...h.matchAll(/<script>([\s\S]*?)<\/script>/g)].map(m=>m[1]).sort((a,z)=>z.length-a.length)[0];fs.writeFileSync("_c.js",b);'
node --check _c.js && rm _c.js
```

`.claude/launch.json` (committed in the repo, with repo-relative paths) defines the servers above (`site` and `subpath`, plus `site-alt` on 8098 as a fallback when another session holds 8097) via **`node tools/serve.js <port> [root]`**, so the preview tooling spawns identically on any clone — Mac, Windows or Linux — with no Python needed. `tools/serve.js` is a zero-dependency static server (Node built-ins only) that mirrors `python -m http.server`: it serves a directory's `index.html` and 301-redirects a slash-less directory request so lessons' `../../` links resolve exactly as on GitHub Pages.

**`node tools/audit.js` is the permanent health check and a required pre-commit gate** (zero-dependency, Node built-ins only; run from the repo root). It exits non-zero on any **error** and cross-checks the whole site against its single sources of truth: coverage per ready lesson (`CHECKS` 3×4, `faq_data.py` 3 Q&As, `QUIPS`, `SNIPPETS` warn-only, `SOFTWARE` info-only, `sitemap.xml`) with no stale/orphan keys; per-lesson HTML (one GA tag, canonical + `og:url` = true URL, `og:type` article, LearningResource + BreadcrumbList + FAQPage JSON-LD all parse, `data-course`/`data-section`, the `Section N.n` eyebrow vs `curriculum.js`, meta description present + 50–160 chars as a warning); root/tool pages (GA, canonical, description, OG; `404.html` GA only); all internal `href`/`src` links resolve on disk with no leading-slash paths; search-index freshness + slug coverage; and the homepage course/lesson counts vs `curriculum.js`. **Structured data (P36, checks 7–8):** every JSON-LD object also passes a per-type required-fields check (name/url; `itemListElement` with well-formed ListItems for BreadcrumbList; `mainEntity` with `acceptedAnswer.text` for FAQPage); every tool page must carry a **BreadcrumbList** (Home → Statistics Toolbox → Tool) and `quiz.html` a **Quiz** block; the homepage's **Organization + WebSite (SearchAction) + ItemList-of-Courses** blocks are deep-checked against `curriculum.js` (course names, per-course lesson counts, track titles, first-lesson URLs, `educationalLevel`s); each lesson's LearningResource must name its own course in `isPartOf` and carry its course's expected `educationalLevel`. **Meta hygiene (P36):** no two audited pages may share a meta description (error), every `<title>` must follow `Thing — StatsCapybara` (the homepage is brand-first), and root-page descriptions get the same 50–160-char length warning as lessons. **Warnings/info never fail the build** — only errors do. Run it (and fix any errors) after every content change and before handing a diff back for review.

**Math (P66): `node tools/math-check.js` is the statistical regression gate — REQUIRED whenever `assets/js/viz.js` or any tool-page math changes.** `audit.js` checks the site's wiring exhaustively but not one line of its math, and the brand promise ("statistics must be correct") had no regression test until this. It loads `viz.js` into a `vm` context under a minimal `window`/`document` shim and runs **218 assertions**, each citing its published source and carrying a tolerance normally set to that source's rounding precision (a value quoted to 4 dp gets 5e-5): the normal family (`erf`/`normCdf`/`normInv`/`normPdf`, plus symmetry identities to machine precision); `tInv`/`chiSqInv`/`fInv` against printed table criticals and the cross-distribution identities (χ²α,1 = z², F.95,1,v = t².975,v, the F reciprocal rule); the documented statcheck case (t = 2.05, df = 28 → two-tailed .0498) plus **quantile↔CDF round-trips across a 7×6 α/df grid** — which is what catches a broken branch a handful of table values would miss; `gammaln`/`gammp`/`betai` identities (Γ(6) = 120, Γ(½) = √π, I₍.₅₎(2,3) = 11/16, both `gammp` branches and both `betacf` branches); density integrals ≈ 1 and pdf-vs-CDF derivative checks; the four **G*Power anchors** through the noncentral trio (d = 0.5 → 64/group, r = .3 → 84, f = .25 k = 3 → N = 159, w = .3 df = 1 → N = 88) plus ncp = 0 collapse-to-central identities; and the documented tool-page constants (d = 0.5 → r = .2425 / OVL 80.26% / U₃ 69.15%, the Fisher-z CI r = .5 n = 30 → [.17, .73]). It runs in **under a second** with Node built-ins only. Two things to know when editing it: **the tool-page sections transcribe formulas from `power.html`/`effect-sizes.html`/`correlation.html`** (which compute against the DOM and so can't be imported) — they assert that `viz.js` still feeds those pages the right numbers, and must be kept in step by hand if a page's formula changes; and **the χ²(1) and F(1,·) density integrals use the substitution x = u²** to absorb their x^−½ singularity at the origin, which plain Simpson cannot integrate. **If math-check ever catches a discrepancy, fix the site, not the test.** It is deliberately kept out of `audit.js` — audit is the universal pre-commit gate, math-check is the math gate; don't fold one into the other.

**Links (P66): `node tools/extlinks.js` is the quarterly P38 external-link helper — network-dependent, so NEVER a commit gate** (a flaky connection would fail a commit that broke nothing; `audit.js` already proves every *internal* link resolves on disk). It scans every `.html` file plus `assets/js/*.js` (the Ko-fi URLs live in `site.js`, not in any page), skipping `.claude/worktrees`, the generated `search-index.js`, and own-domain `statscapybara.com` links, then fetches each unique URL with a browser User-Agent, a 15 s timeout, redirect-following and concurrency 6, and reports grouped **ok / bot-blocked-but-known-fine / broken** with the files each link appears in. The `ALLOW` table carries the P38 allow-list (**ko-fi 403** Cloudflare, **LinkedIn 999**) and is **status-specific on purpose** — a host on the allow-list that returns anything other than its catalogued status is reported as genuinely broken with a NOTE, so a real 404 can't hide behind a familiar failure. Each entry records when it was last verified in a real browser; **re-verify during each P38 run rather than trusting the list forever.** `xmlns="http://www.w3.org/2000/svg"` is excluded as a namespace identifier, not a link. Default exit is 0 whatever it finds; `--strict` exits 1 on a genuine break, `--verbose` lists source files for every link.

**Voice (P40): `VOICE.md` at the repo root is the editorial law for all prose** — lesson bodies, FAQ answers, guides, posters, tool-page copy, meta descriptions, and the injected strings in `checks.js`/`software.js`/`snippets.js`. Any session that writes or edits prose reads VOICE.md first. Its measuring stick is **`node tools/prose-lint.js`** (zero-dependency, run from the repo root): it extracts rendered prose from every lesson, guide, and audited root page (a lesson's baked-in FAQ block is excluded and its answers linted separately from `tools/faq_data.py`, which is their single source of truth), plus every meta description, and counts em-dash load and the machine-tell constructions against the hard budgets in VOICE.md. The `PATTERNS` table at the top of the script **mirrors VOICE.md's HARD RULES — change them together, in the same commit** (both files carry this warning). Modes: default = full per-page report sorted worst-first + sitewide summary + worst-10; `--page <path>` = one page with every hit as a `»match«` snippet; `--strict` = exit 1 if any hard budget is exceeded (the exit gate for the P41–P46 voice passes). It is **deliberately not wired into `audit.js`** — voice is editorial judgment, not build health, and the site ships while budgets are still being worked down. JS-injected strings (checks "why"s, software tips, snippet comments, QUIPS) are outside the linter's scope; P46 applies VOICE.md to those by hand, and quips are exempt brand voice.

Deploy = `git` commit + push (from the repo root) (the user pushes via GitHub Desktop). GitHub Pages serves the `main` branch from `/ (root)`. `CNAME` sets the custom domain `statscapybara.com`. **PWA cache-bump step:** if a deploy changes any **precached shell asset** (`styles.css`, `site.js`, `curriculum.js`, `viz.js`, `assets/fonts/Inter.woff2`, an icon, or `offline.html`), bump **`CACHE_VERSION`** in `sw.js` (e.g. `sc-v1` → `sc-v2`) so returning visitors' service worker drops the old cache and reprecaches. Lesson/prose HTML edits **don't** require a bump (HTML is network-first — always fresh online), but bumping never hurts. **Since the SWR update path (below), a bump is the fast path, no longer the only one:** CSS/JS are stale-while-revalidate, so a changed `styles.css`/`site.js` propagates on the visitor's next navigation even if you forget to bump — and a bump additionally triggers `site.js`'s auto-reload so the change applies within the same visit. **Crucially, never reuse a `CACHE_VERSION` string across two different byte-contents of a precached asset** (e.g. editing `styles.css` twice in one uncommitted session but bumping only once): a browser that precached the intermediate state keeps serving it until the string changes again. Each distinct shell state that could reach a browser needs its own version.

## Architecture (the parts that span files)

**Single source of truth — `assets/js/curriculum.js`.** Defines all courses and sections (`{ n, slug, title, ready }`, plus `accent` and `track` per course) and a derived flat list. The homepage curriculum grid, every lesson's sidebar, and the prev/next links are all generated from it. To add / rename / reorder a lesson, edit here. A section without `ready: true` renders as a non-clickable "coming soon" item. **Tracks:** `window.TRACKS` is the ordered list of curriculum tracks (`core` → "The Statistics Core", `toolkit` → "The Research Toolkit"); each course carries a `track` (defaulting to `"core"`). `site.js`'s `renderCurriculum` groups the homepage cards by track and draws a track heading (`.track-head`, spanning the grid row) above each group **only when more than one track is populated** — both tracks are populated today, so the homepage shows the two track headings (with a single track it would render one flat grid, as it did pre-Methods). **Since P60 each track heading is an `<h2 class="track-head">` with a stable id `#track-<trackId>`** (`#track-core` / `#track-toolkit`) — the deep-link targets of the nav's track tabs (h2 because P60 also removed the old section h2 above the grid, keeping the heading order intact; the styles are class-scoped, so nothing changed visually). Each `TRACKS` entry also carries a one-line **`desc`**, rendered under its heading as `.track-desc` (P32); course cards append a computed "· N lessons" to their subtitle line. The `.courses` grid is `auto-fit`/`minmax`, so it wraps gracefully as courses grow. Visible homepage totals are computed at runtime from the curriculum: any element with `data-count="courses" | "lessons" | "courses-word"` is filled by `site.js` (`renderCounts`), so they can't drift; the static counts baked into `<meta>`/OG/JSON-LD stay hardcoded and are guarded by `audit.js` check #6 instead.

**Shared chrome — `assets/js/site.js`** runs on every page and builds: the nav (capybara SVG logo + "StatsCapybara" brand — the brand is the home link). **P60 rebuilt the nav tabs around the site's real shape: "Statistics Core ▾" and "Research Toolkit ▾" — one dropdown per track, generated from `window.TRACKS` + `CURRICULUM` (never hardcode course lists) — alongside the "Statistics Toolbox ▾" pill; the old Curriculum and About tabs are retired** (the homepage `#about` section stays, reachable via a quiet JS-injected **About link in every footer** — `renderFooterAbout()`, `.footer-about`, flex `order:1` so it sits between the tagline and the Ko-fi button; **P68 added a second footer link beside it, `renderFooterFeedback()` / `.footer-feedback`, "Spotted a mistake? Tell me"** — a `mailto:` (not a GitHub issues link: the audience is students, most without GitHub accounts) whose **subject carries the page's own path**, taken from the page's `<link rel="canonical">` when it has one so the report names the clean public URL rather than whatever host served it. Styled a shade quieter than About — it's an invitation, not a destination). Each track dropdown lists **only that track's courses** (`.nav-drop-item` rows: `.nd-dot` accent dot + title + subtitle); **a course row links to the course's landing page `<course>/`** (P61 — the same entry URL the homepage ItemList JSON-LD and the homepage course-card title now use; it was the first `ready` lesson pre-P61), and on a lesson OR course-landing page the current course's row lights up. Clicking a track tab itself goes to the homepage scrolled to that track (`#track-core` / `#track-toolkit` — see the curriculum.js note; BASE-aware, so it works from lesson depth). The **Toolbox dropdown renders grouped exactly like toolbox.html** — `TOOLBOX_GROUPS` order, but its titles render as **text-only** uppercase `.ndp-ghead` headers (the leading emoji is stripped in `renderNav` — the homepage grid + toolbox.html keep the emoji versions), **green-accented via `var(--group-head)`** (a per-theme token — deep green `#15803d` in light so it clears 4.5:1 on the white panel, bright `#22c55e` in dark — since the raw `--success` green fails contrast on white), each group divided by a `border-top` — with compact one-line rows (`.ndi-compact`: emoji + title, no descriptions) split across **two columns of whole groups** (`.ndp-col`; order preserved, greedy height-balanced in `renderNav`), so all ~24 tools stay visible on a 768px-tall viewport with no scrolling; the panel is `width:max-content` anchored `right:0` (don't give the columns `flex:1` — equal-width columns clip the long guide titles). **Interaction parity for all three menus:** hover/focus-within opens (CSS-driven, with the invisible hover bridge), clicking the tab navigates, JS mirrors open state onto `aria-expanded`, and **Escape force-closes the open panel** (a `.closed` class that out-cascades `:hover`/`:focus-within` and clears when pointer/focus leaves) returning focus to its tab; on mobile all three flatten to plain links (track tabs → the homepage track anchors, Toolbox → the hub; panels suppressed, `aria-expanded` stays false, "go there" chevrons). **The Toolbox keeps its P55 tinted pill** (🧰 in `.ndb-emoji` + label in `.ndb-label`, weight 700, primary-tint background/border on `.nav-drop-btn`, fully rounded) so it stands apart from the plain track tabs (`.nav-drop-tab`, styled as `.nav-link`s), and the pill styling carries into the mobile menu row (where the mobile block re-squares its radius). **Active states:** a lesson page lights the tab of ITS track (course → track via curriculum.js), any tool or guide page lights the Statistics Toolbox, and the homepage lights nothing. Quiz and Glossary live **only inside the toolbox** — no separate top-level links. There is deliberately **no Ko-fi pill in the nav** (Hakan found it "too desperate"); support links live only in the footer (Ko-fi image button). Also in the nav: a **search pill** (`.nav-search-btn`, icon + "Search" + `/` kbd hint, collapses to an icon under 1200px) + mobile hamburger, theme toggle. site.js further builds the homepage curriculum grid **and full toolbox grid**, the lesson sidebar (highlighting the current `data-section`; `renderSidebar` groups its collapsible course `<details>` **by track**, drawing a `.sb-track-head` — same quiet uppercase-label-plus-trailing-rule as the homepage's `.track-head` — above each track's courses **only when more than one track is populated**, so "Statistics Core" / "Research Toolkit" separate Stats 4 from Methods instead of one undivided run), prev/next, and the Ko-fi image button injected into every footer. The **`TOOLBOX` array in `site.js` is the single source of truth for tool pages** (each entry has a `group`: guide/calc/practice/read) — it renders the nav dropdown, the homepage `#toolbox-grid`, and (exposed as `window.TOOLBOX`) the grouped grid on `toolbox.html`; add any new tool page there. **Since P55 the homepage `#toolbox-grid` shows the FULL toolbox, grouped**: `renderToolbox()` renders every `TOOLBOX` entry under its group heading (`.tbx-head`/`.tbx-desc` rows that span the grid the way the curriculum's track heads do), so a new tool page appears on the homepage automatically — the P32-era `star` flags and the dashed "All N tools →" card are gone. The four group titles/blurbs live in **`TOOLBOX_GROUPS`** in `site.js` (exposed as `window.TOOLBOX_GROUPS`), which `toolbox.html`'s grouped grid reads too — edit group wording in one place. **P60 removed the "Start here" persona cards and the "Jump in wherever you are" h2** from the homepage (the curriculum section keeps its intro paragraph, the track headings are the section's headings now, and the nav's track dropdowns took over the personas' entry-point job — the persona CSS was deleted); the hero's primary CTA ("See statistics in motion") points at `stats-1/central-limit-theorem/` for a striking first impression and the secondary CTA at `plan.html`; the old "Why it's different" `.features` section was removed from the homepage in P55 (the shared `.feature` CSS stays in `styles.css`). `site.js` also holds **`QUIPS`**: one capybara one-liner per page (keyed by lesson slug or root file name, with a hash-picked fallback pool), shown in a `.sb-capy` box injected **directly below the highlighted lesson in the sidebar** (always in view). The footer keeps its static "Made for visual learners." tagline — an earlier footer-quip render was deliberately reverted, so tool pages (which have no sidebar) don't surface their quip anywhere visible yet — but **every new lesson/tool page still needs a QUIPS entry** (the audit enforces it). It computes `BASE` in **three states**: `"../../"` on lesson pages and guide pages (`body[data-section]` or `body[data-guide]`, two folders deep), `"../"` on **course landing pages** (`body[data-course-home]`, one folder deep — P61), else `""` at the root; it prefixes every generated link with it, so all links stay relative; homepage anchors are built as `(BASE || "./") + "#about"` so they also work from root-level tool pages. It also injects site-wide extras once (so no per-page edits): a **skip-link** + `main#main-content`, `role="img"`+`aria-label` on every `.viz canvas`, the `<link>`s for the SVG favicon / `apple-touch-icon` / `site.webmanifest` + **two media-scoped `theme-color` metas** (indigo in light, dark-bg `#0b1120` in dark), and it **registers the offline service worker** (`registerSW()` — `BASE + "sw.js"`, feature-detected, deferred to `load`, and fully swallowed so a SW error never breaks a page). See the **Offline PWA** note below. **Viz PNG export (P48):** `injectVizExport()` puts a small **"PNG ↓"** button on every `.viz` block that contains a canvas — next to the `.viz-title` (wrapped in a `.viz-head` flex row) or, on a titleless calculator viz, in a right-aligned `.viz-exportbar` at the top of the block. Click downloads that block's **largest rendered canvas** at **2× CSS size** via an offscreen `toDataURL` (the current theme's canvas background is painted underneath so dark-mode exports aren't transparent), filename `statscapybara-<slug>-<n>.png` (`<n>` = 1-based block index on the page). It's a real `<button>` (keyboard-accessible, aria-labelled), hidden in `@media print` (and by the existing `.viz button` print rule), and never touches canvases outside a `.viz` (the homepage hero is safe); a `.viz` or canvas with `data-no-export` is skipped, and a canvasless "viz" (e.g. `apa.html`) gets no button. **Lesson embed mode (P48):** a lesson URL with **`?embed=1`** renders as a bare interactive widget for an `<iframe>` — `init()` detects `EMBED` (lesson pages only), adds `body.embed-mode`, and **skips all chrome renders**, so `styles.css`'s `body.embed-mode` rules hide the nav/sidebar/footer and trim `.lesson` to just the eyebrow + `h1` + `.viz` block(s) with their controls; `renderEmbedFooter()` appends one line linking back to the full lesson (`target="_top"`, the lesson's absolute **canonical** URL, so it escapes the frame and works from any host). The lesson's own inline viz script runs independently, the canonical still points at the clean URL (no SEO wrinkle), and the head GA tag fires exactly once. Progress isn't recorded in embed mode. **Lesson state presets (P67):** **`window.SC.preset(map)`** lets a URL preconfigure a lesson's interactive, so an instructor can embed not just a lesson but the configuration their slide is about — the lesson counterpart to `power.html?sc=&es=` / `apa.html?a=&v=` / `plan.html?test=`. A lesson **opts in** by calling it at the **END of its boot** with a map of short query keys to appliers, in **four forms**: a **selector for a form control** (sets the value and dispatches `input` + `change` — what moving the slider by hand does); a **selector for a `.seg` strip** (clicks the button whose data-\* value matches — any data-attribute name, numeric values compared numerically so `?alpha=.05` finds `data-a="0.05"` — so the lesson's own handler runs and there is no second code path); **`{ el: selector, scale: n }`** for the common slider that carries hundredths of the value the lesson *prints* (`?z=1.96`, `?r=0.3`, `?prior=0.25`) — the helper scales, snaps to the control's own `step` grid and clamps to its own `min`/`max`, so **a lesson never restates those bounds in JS**; and a **function** getting the raw string, for anything that isn't a control. Rules the helper enforces: **absent/unknown/garbage params are silently ignored** (every applier runs in its own try/catch, strict numeric parsing rejects `0x10`/`12abc`/`NaN`/`Infinity`, unknown `<select>` options and unmatched seg values are left alone — a mangled URL still loads the plain default lesson); it runs **after** the lesson's init so the **frozen-noise law holds** (a preset moves controls, it never reseeds); and it **composes with `?embed=1`** (independent params). **Section share-links (P68):** `renderSectionLinks()` puts a small copy-link button on **every `h2` of a lesson or guide** (not tool or course-landing pages), so a lecturer can hand out one section rather than a whole page. Ids come from **`ensureH2Ids()`** — extracted from `renderTOC()` in P68 and now shared by both, so the mini-TOC and the share-links point at the same anchors: hand-written ids win, the rest are slugified from the heading text, and dedupe checks **every** id already on the page (not just the other headings) so a heading can't silently steal an existing anchor. Three constraints shape the button and are worth keeping if you touch it: **zero layout shift** (it is in flow and occupies its box from first paint — only `opacity` changes; below 700px, where a heading often fills its last line exactly and an in-flow button would wrap to a line of its own, it switches to `position:absolute` in a permanently reserved right gutter, so still nothing moves); **no hover-only affordance** (invisible until hover or focus on a fine pointer, permanently half-lit on a coarse one, with a `::before` inset growing the touch target to ~44px without growing the box); and **no clipboard, no button**. Confirmation is an **icon swap** to a green check inside the same fixed box, because widening the button to fit the word "Copied!" would shove the heading — so `flashCopied()` gained a **`data-copy-flash` slot**: an icon button carries a visually-hidden live region that takes the wording, while text buttons keep the old label-swap behaviour unchanged. **Offline PWA (P33) — `sw.js` + `offline.html` + `site.webmanifest`.** The site is installable and works offline once visited. **`site.webmanifest`** uses only **relative** paths (`start_url`/`scope`/`id` = `"./"`, icons `assets/icon-*.png` incl. a `maskable` variant) so it survives subpath hosting; it's linked BASE-aware by `site.js`'s `injectHead()`. **P68 added three `shortcuts`** (the long-press / right-click menu on an installed PWA): Continue learning → `progress.html`, Statistics Toolbox → `toolbox.html`, Course quiz → `quiz.html`. Their `url`s are **relative like everything else here** — verified to resolve against the manifest's own URL and stay inside `scope` under the `subpath` server, which is the whole reason the rule exists. No shortcut icons (the OS falls back to the app icon). **`sw.js`** (site root; zero-dependency, Node/browser built-ins only) precaches the **app shell** (`styles.css`, `site.js`, `curriculum.js`, `viz.js`, the font, favicons+icons, `site.webmanifest`, `offline.html`) into a cache named by **`const CACHE_VERSION`**, then serves three ways: **stale-while-revalidate for CSS/JS** (`.css`/`.js` — the cached copy paints instantly *and* a fresh copy is fetched in the background to update the cache, so a changed stylesheet/script reaches the visitor on their next navigation on its own, with no cache-clearing and no reliance on a version bump), **cache-first for immutable assets** (fonts/images/icons — revalidating them every load would just waste bandwidth), and **network-first for HTML navigations** (an online reader never gets a stale lesson — the network copy wins and is cached as a fallback; a cached copy serves only when offline). Uncached navigations offline fall back to **`offline.html`** (self-contained like `404.html` — no external refs, inline capybara, and it lists the pages this browser has cached via the Cache API). `activate` deletes non-current caches and `clients.claim()`s; `install` `skipWaiting()`s, so a **`CACHE_VERSION` bump** cleanly replaces the old cache — and because `site.js`'s `registerSW()` reloads the page once on `controllerchange` (**guarded**: only when a worker already controlled the page at load, so a first-ever install never reloads, plus a one-shot flag so it can't loop), a bumped deploy's fresh CSS/JS apply within the **same visit**, not the next. **This is the answer to "why do returning visitors see old CSS?": pure cache-first only refreshed on a bump *and* needed a second load; SWR + the auto-reload remove both, so no one ever has to clear their cache.** Cross-origin requests (GA, Ko-fi) pass straight through — never cached. `sw.js`/`offline.html` are **not** in `audit.js`'s `ROOT_PAGES` (they're self-contained, like `404.html`), and not in `sitemap.xml`. Verified end-to-end (P33): registration + precache, offline lesson load with the server stopped, offline.html fallback, the `CACHE_VERSION`-bump update path (old cache purged), and correct scoping under the `subpath` server.

**Per-page SEO & analytics — hardcoded in each `<head>` (no build step, so *not* generated by `site.js`).** Every page carries the Google Analytics 4 tag (`gtag.js`, measurement ID `G-80HCM6EZVN`) immediately after the opening `<head>` — exactly **one per page**, including `404.html`; never add a second. Every indexable page also has a `<link rel="canonical">`; lessons, `quiz.html`, and the tool pages carry Open Graph / Twitter cards built from that page's own `<title>` + meta description plus an OG image (`og:type` = `article` for lessons, `website` for homepage/quiz/tools) — **each lesson points its `og:image`/`twitter:image` at its course's card `assets/og-<course>.png`; the homepage and tool pages use the brand default `assets/og.png`** (see the OG-image note below); **Structured data (upgraded in P36):** the homepage carries three JSON-LD blocks — an **Organization** (with the founder Person), a **WebSite** (keeping the `?q=` **SearchAction** that powers the search deep link), and an **ItemList of one `Course` object per course** (name `Title: Subtitle`, description `N interactive lessons — part of <track title> track.`, url = the course's first lesson, plus its `educationalLevel`) — all deep-checked against `curriculum.js` by `audit.js` check 7, so **adding/refactoring a course means updating the homepage ItemList by hand** (the audit fails until it matches). `quiz.html` has a minimal **Quiz** block (`about`: the nine courses) and every tool page a **BreadcrumbList** (Home → Statistics Toolbox → Tool); **every lesson has a JSON-LD `[LearningResource, BreadcrumbList]` block** just before `</head>` (built from that page's own title/description/canonical — retarget it when copying a lesson). ## Conventions / gotchas

- **Paths must be relative.** Never use leading-slash `/assets/...` or `/stats-.../`. Lesson pages (depth 2) reference `../../assets/...` and link to `../../<course>/<slug>/`; root pages (`index.html`, `quiz.html`) use `assets/...`. This keeps the site working under any hosting base path. Verify with the `subpath` server above.
- **`404.html` is intentionally self-contained** (inline CSS, no external refs, JS-computed "home" link) because GitHub serves it at arbitrary URL depths.
- **Statistics must be correct.** Interactives are verified against known values (t/F/χ² critical values, G*Power, Beta quantiles). Use the `VIZ` special functions rather than rough approximations, and sanity-check new math (e.g. via `node -e` against a known case).
- **Frozen-noise interactives.** Sliders must transform the *same* data points, never redraw a fresh random sample — students lose the intuition if dots reshuffle on every tick. Pattern used across all lessons: a `seed()` fills pools of fixed `VIZ.randn()` / `Math.random()` draws (sized to the slider maximum); a deterministic `gen()`/`rebuild()` maps `(pool, slider values) → data`; slider `input` handlers call only the deterministic step; the explicit "New sample/samples/people/studies" button calls `seed()` first. Verify with a round-trip: move a slider away and back — every readout must return to the exact same value.
- **Canvas cursor convention (P47).** Every interactive canvas declares what it does with its cursor: **draggable** (move a point, rotate the cloud) → `cursor:grab` at rest, `grabbing` while the pointer is captured (set `grab` inline in the canvas markup or on boot, flip to `grabbing` in `pointerdown`, restore in `pointerup`/`pointercancel`); **click-to-select/add** → `pointer` (set it only while there's something to click — see `correlation.html`'s `drawScatter`); **axis-constrained drag** (the classification-metrics threshold) → `ew-resize`; **display-only** → leave the default. If the affordance exists only in one mode, scope the cursor to that mode (`ml/dimensionality-reduction` shows `grab` only in its 3-D view).
- **Touch conventions (P65) — the finger counterpart to P47's cursor rules.** Three rules, all cheap to keep:
  - **A canvas that captures pointer drags declares `touch-action`.** Without it the browser treats the drag as a page scroll and the interactive fights the finger. Free-drag → `touch-action:none`; a drag locked to one axis may use `pan-y` to leave vertical scrolling alone. Declare it **in the canvas markup** (`style="touch-action:none;cursor:grab"`) alongside the cursor, not from JS on boot — one place to read, and it's right even before the lesson's script runs. **Display-only canvases must NOT declare it** (`touch-action:auto` is correct: the page should scroll normally when a finger lands on a chart it can't manipulate — e.g. `stats-2/correlation`'s `ans-canvas`, `stats-4/signal-detection-theory`'s `sdt-roc`). Seven canvases drag today: the point-drags (`stats-1/describing-data`, `stats-2/correlation`, `stats-3/assumptions-of-regression`), `ml/clustering-kmeans`, `ml/dimensionality-reduction`, and the two criterion/threshold drags (`stats-4/signal-detection-theory`, `ml/classification-metrics`). Pair `pointerdown` with **both** `pointerup` and `pointercancel` — a cancelled touch otherwise leaves the drag stuck on.
  - **Hit-test radii come from `VIZ.grabRadius(base)`, called at pointerdown** (`viz.js`, with `VIZ.coarsePointer()` underneath). Radii tuned by eye are mouse-sized (14–18px) and a finger pad needs ~24px, so the helper returns `base` unchanged on a mouse and `max(base, 24)` on a coarse pointer — **mouse behaviour stays byte-identical**, which is the point. Read it live at pointerdown rather than caching at boot, so hybrid touchscreen laptops and device emulation both get the right answer; square the result where the hit-test compares squared distances (`ml/clustering-kmeans`). The two criterion drags need no radius — they grab anywhere on the canvas. Note `stats-1/describing-data` loads `viz.js` **only** for this helper (it still has its own local `fit()`); any early lesson calling a `VIZ.*` helper must actually load the script.
  - **No affordance may be hover-only.** Anything revealed on `:hover` needs a touch path — a tap, or made permanent under `@media (pointer: coarse)` (as `.wt-opt::after`'s "→" chevron is). The nav's track/Toolbox dropdowns are compliant by construction: they flatten to plain links below 860px, and above it tapping the tab navigates to a page listing the same items.
- **Narrow-screen layout (P65).** The site is verified to have **no page-level horizontal scroll at 360px** across every lesson, tool, guide and course page. Two patterns carry it, both already in `styles.css`: a **`.seg` never clips** — it has `max-width:100%` + `overflow-x:auto`, so a many-tab strip scrolls inside itself instead of losing its last tab (generalising `apa.html`'s older `#ana-seg` fix), and `.control:has(.seg)` gets `min-width:0` so that strip can't pin its column to full width; and the rows that hold a seg (`.sw-head`, `.tc-head` — the injected SPSS/JASP and R/Python headers) **wrap**, so the seg drops to its own line rather than being squeezed. Corollary for new work: **a hardcoded `min-width`/`minmax()` floor above ~280px will overflow a phone** — write `min-width:min(300px,100%)` and `minmax(min(330px,100%),1fr)` (what the five stats-3/4 slider controls and the three cheat posters now use). A `white-space:nowrap` table cell can also hold a table wider than the screen; scope it to `@media screen and (min-width:561px)`-style rules so print keeps its one-line layout.
- **Interaction feel (P47) — the shared tactile layer** lives in `styles.css` + `site.js`; new pages get it for free, don't re-implement per page: **(a)** every `[id]` carries `scroll-margin-top` so anchor targets land clear of the fixed nav — never hand-offset a heading; **(b)** every clickable (buttons, cards, chips, seg buttons) shares one `:active` press rule (`translateY(0) scale(.985)`) — add new interactive classes to that selector list rather than writing bespoke press states, and keep card hover lift at −2px/`--shadow-lg`; **(c)** every copy button calls **`window.SC.copied(btn)`** (site.js) after its clipboard write — one wording ("Copied!"), 1.4 s revert, green `.copied` tint, `aria-live` polite; **(d)** `<details>` reveals animate via `::details-content` (progressive enhancement; instant under reduced motion) — keep any `::details-content` selector in its **own** CSS rule (comma-mixing kills the whole rule in non-supporting browsers), and the `@media print` block forces `block-size:auto` so the beforeprint force-open still prints full-height; **(e)** wide content scrolls inside a **`.hscroll`** container with edge-fade cues — site.js's `setupHScroll()` auto-wraps every `table.ref-table` and tags the known overflow containers (`HS_SELECTOR`); give any new horizontally-scrolling element the `hscroll` class and the fades come free; **(f)** range inputs share one sitewide family (soft accent track, ringed round thumb, 44px touch height on coarse pointers) driven by `--range-accent`/`--range-thumb` — override the variables (like `.hero-slider` does), never write new `::-webkit-slider-*`/`::-moz-range-*` rules per page; **(g)** **in-prose links are Wikipedia-style site-wide (P54)** via one scoped rule in `styles.css`: body-copy links inside a `.lesson` article (`p`/`li`/`td`/`th`/`.callout`/`.faq-a`, plus the About bio + `.a11y-statement`) are **coloured but NOT bold and NOT underlined at rest** — the underline appears **only on hover** (and the global focus ring on focus), so a link never interrupts calm reading. **Never add `font-weight` to a prose link** — bold in prose is reserved for real `<strong>` emphasis. Because colour is the only at-rest cue, **`--link`** is tuned per-theme to clear TWO WCAG gates at once: ≥4.5:1 vs the surface (readability) AND ≥3:1 vs the body text (perceivable without an underline, satisfying 1.4.1) — light `#5850ec`, dark `#6f7bf2`; **don't substitute raw `--primary`/`--primary-light`, which fail the ~3:1-vs-text gate.** (One inherent limation: inside `.callout`/`.faq-a` the *surrounding* text is `--text-muted`, so link-vs-muted-text can't also hit 3:1 by luminance — the hue difference + hover/focus carry it, matching Wikipedia's own behaviour.) UI chrome keeps the quiet `a{color:inherit}` base and its own heavier styling (buttons, cards, nav, sidebar, prev/next, interactive-box CTAs, poster `.sec` badges): `.btn`, `.lesson-toc`, and datasets' `.ds-index` are excluded in the selector, and cards/nav/sidebar/prev-next are untouched by construction (their anchors don't sit in those prose elements). So: content links in prose need nothing; a new chrome link-LIST inside an article belongs in a classed container (not bare `<li><a>`) and, if it's `li`/`td`-shaped, gets added to the rule's exclusion list. The shared `@media print` block forces plain black underlines on every link; a page that prints links differently (e.g. `plan.html`'s plan card) uses its own `text-decoration:none !important` to override that.

  - **Sidebar CLS on mobile.** The lesson sidebar is JS-injected after paint; in the stacked mobile layout it must render **after** the article (`.lesson { order: 0 } / .sidebar { order: 1 }` in the `max-width: 860px` block) so filling it extends the page below existing content instead of shoving the article down ~800px. Don't reorder it back above.
  - **Web-font CLS.** A metric-matched `@font-face { font-family: "Inter Fallback"; src: local("Arial"); … overrides }` sits first in the `--font` stack (before `system-ui`), so the fallback occupies Inter's exact line box and the swap causes no reflow. Keep it in the stack; if Inter's metrics ever change, retune the `ascent/descent/size-adjust` overrides.
  - **Canvas backing store — DPR cap.** `VIZ.fit()` (and the handful of pre-VIZ local `fit()` copies in `index.html` + early `stats-1` lessons) caps `devicePixelRatio` at **2** (`Math.min(dpr, 2)`): beyond 2 the backing store grows quadratically for no visible gain on flat charts. New canvas code should use `VIZ.fit`; if you must roll your own, cap DPR the same way.
  - **Resize handlers — rAF-coalesced.** Wrap a canvas's resize/redraw in **`VIZ.rafThrottle(fn)`** so a burst (a window `resize` **and** a `ResizeObserver` both fire per resize) collapses to one redraw per frame — see the tool pages (`tables.html`, `power.html`, `correlation.html`, …). Older lessons still use direct `resize` listeners; that's fine (resize is a rare event) but new work should use the helper.
  - **JS loading.** Never make `search-index.js` (~450 KB) eager — it's lazy-loaded only when the search overlay opens. GA stays `async` (don't touch it). The per-lesson bundles (`checks.js` / `software.js` / `snippets.js`) are injected async by `site.js` and cache across the session — non-blocking, acceptable under the no-build design. **No build step / bundler / minifier** — every optimization must preserve that.
- **Print handouts (established in P30; every lesson prints as a clean, professor-ready handout, entirely from the shared layer — new lessons/tools get it for free).** The whole system lives in **one `@media print` block in `styles.css`** plus **`site.js`'s `setupPrint()`**:
  - **What prints:** prose, callouts, formulas/`.ref-table`s, the frozen `.viz` canvas + its `.viz-title`/`.stat-row` readouts, the injected **APA write-up** and **R/Python snippet** (reference material). **What's hidden:** all site chrome (nav, `.sidebar`+`.sb-capy` **quip**, `.lesson-nav`, footer, Ko-fi, search, resume bar, `.lesson-progress-head` incl. the print button itself), the **viz controls** (`.controls`/sliders/buttons/`.seg`, and the R/Python language toggle), and the two **interactive** injected blocks — `.checks` and the SPSS/JASP `.software` block. **Decision:** the capybara **quip is hidden in print** (it lives in the always-hidden `.sidebar`), so serious lessons (Ethics) print without a flippant one-liner.
  - **Dark-mode-safe:** the print block **redefines the surface/text/border/shadow CSS variables to a light palette** (targeting both `:root` and `html[data-theme="dark"]`), so a reader in dark mode still gets white cards + black ink, not dark boxes. Don't set per-element print backgrounds — override the vars.
  - **`setupPrint()` (lesson pages only)** injects the **"Print this lesson"** button into `.lesson-progress-head` (next to mark-complete, `.print-btn`, itself hidden in print) and a **discreet fixed `.print-footer`** carrying the page's clean canonical URL (e.g. `statscapybara.com/stats-1/central-limit-theorem`), repeated per page. On **`beforeprint`** it force-opens every closed `<details>` (the FAQ — the `.checks` block is skipped) and **snapshots each `.viz canvas` to an `<img>`** (some browsers rasterise `<canvas>` blank on the print sheet); **`afterprint`** reverts both. It's guarded against double-firing and also listens to the `print` media-query change (Safari fires no before/afterprint). `formulas.html` (which had its own print button) and `glossary.html` (now given a matching print button) inherit the same block since both use `article.lesson`.
